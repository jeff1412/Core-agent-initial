# PR Review Playbook — For Human Owners
*Version 1.0 — April 2026*

## 👋 Hello!
The ASC Agent is now working for you. It will generate code and open **Draft Pull Requests** in GitHub. This guide explains how you review and approve its work.

### 1. The Notification
When the agent finishes a task, you will see a message in your product channel (e.g., `#mg-dev`).
- **Read the Summary**: The agent will explain in plain language what it changed.
- **Click the Link**: Click the GitHub PR link to see the code.

### 2. The GitHub Review
The PR is opened as a **Draft**. This means it is "Work in Progress" and cannot be merged yet.
- **Look at "Files Changed"**: Check if the code looks reasonable.
- **Look for Flags**: The agent will tell you if it had security concerns or if it touched something it wasn't supposed to.

### 3. Approving and Merging
Once you are happy with the code:
1.  **Mark as Ready**: Click "Ready for review" in the GitHub PR.
2.  **Approve**: Click "Files changed" -> "Review changes" -> "Approve".
3.  **Merge**: Click the "Merge pull request" button.
4.  **Delete Branch**: Click "Delete branch" to keep the repo clean.

### 4. What if the code is wrong?
If the code isn't what you wanted, simply close the PR or leave a comment. You can then post a new task brief in `#agent-intake` with more specific instructions.
