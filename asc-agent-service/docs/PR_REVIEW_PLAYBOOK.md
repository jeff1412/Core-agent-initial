# PR Review Playbook — ASC Agent Service
Version: 1.0 | Owner: ASC Creative (Tim)

This playbook describes how to review and approve code generated by the ASC Agent. Follow these steps to ensure safe and high-quality deployments.

## 1. Receive the Notification
When the agent completes a task, you will receive a message in the relevant product channel (e.g., `#mg-dev` or `#janus-dev`).
- **Check the Summary:** Read the plain-language description of what was changed.
- **Click the PR Link:** Navigate to the Draft Pull Request in GitHub.

## 2. Review the Pull Request (GitHub)
The agent provides a structured PR description. Verify the following sections:
- **Task Summary:** Does this match your original request?
- **Changes Made:** Review the list of modified files.
- **Testing Performed:** The agent documents simulated tests.
- **Data & Privacy Flags:** Check if the agent identified any sensitive data handling.
- **Do Not Touch Violations:** Ensure the agent "Stayed in its lane" (did not modify restricted modules).

## 3. Examine the Code (Files Changed tab)
- **Sanity Check:** Does the logic look reasonable?
- **Canadian English:** Check for any user-facing strings (must use 'u' in 'colour', etc.).
- **Security:** Ensure no hardcoded keys or dangerous patterns were introduced.

## 4. Decision Time
- **Approve:** If it looks good, click **Review changes** → **Approve**. You can then **Merge** the PR if you are ready to deploy.
- **Request Changes:** If something is wrong, add a comment in GitHub. *Note: Currently, you should then post a revised brief in Mattermost to re-trigger the agent.*
- **Escalate:** If the agent flagged a module for "Human Review," you must manually complete that specific part of the logic before merging.

## 💡 Pro Tips
- Treat the agent like a junior developer who is very fast but needs a second pair of eyes.
- If the agent makes a mistake, update the product's `AGENT.md` to prevent it from happening again.
